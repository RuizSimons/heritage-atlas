# Heritage Atlas

A globally-scalable cultural-heritage architecture atlas built with Hugo.

## What This Is

This site documents significant architectural heritage buildings worldwide, presenting them as a living record of cultural and technical information. The seed collection includes the Rietveld Schröder House, Westerkerk, and Groninger Museum.

## Data Synchronization Workflow

The site reads its data from the `data/` directory inside this repository. This ensures the site is self-contained and can build successfully on GitHub Actions without external dependencies.

**Data files are managed in the parent `heritage-app` directory and synced to this repo before each build:**

- `data/index.json` - The building index (auto-generated by `build_index.py`)
- `data/building.example.md` - Example building markdown template
- `data/seed/*.md` - Individual building markdown files

When you add a new building or rebuild the index, run the deploy script which automatically syncs all data files before building the Hugo site.

## Adding a New Building

To add a new building to the atlas, use the interactive script:

```bash
python C:\Users\simon\heritage-app\scripts\add_building.py
```

Or with Wikipedia pre-fill:

```bash
python C:\Users\simon\heritage-app\scripts\add_building.py --wiki "Building Name"
```

For dry-run testing (no files written):

```bash
python C:\Users\simon\heritage-app\scripts\add_building.py --dry-run --wiki "Building Name"
```

The script prompts for required fields and generates a valid JSON record that conforms to the project's JSON Schema v0.1.0 data model.

After adding a building, run the deploy script to sync the data and rebuild the site.

## Deployment Workflow

### One-Time Setup

1. **Install GitHub CLI** (if not already installed):
   ```bash
   winget install GitHub.cli
   ```

2. **Authenticate with GitHub**:
   ```bash
   gh auth login
   ```
   Follow the prompts to authenticate via browser or device code.

3. **Create the repository**:
   ```bash
   gh repo create heritage-atlas --public --source=. --remote=origin --push --description "Globally-scalable cultural-heritage architecture atlas"
   ```

4. **Enable GitHub Pages**:
   ```bash
   gh repo edit --enable-pages --pages-source-branch gh-pages --pages-source-path /
   ```

### Ongoing Deployment

After the one-time setup, every push to the `main` branch automatically deploys the site via GitHub Actions. The workflow:

1. Builds the Hugo site with `hugo --minify`
2. Deploys the `public/` directory to the `gh-pages` branch
3. Your site is live at `https://<username>.github.io/heritage-atlas/`

### Local Deploy Script

Use the convenience script to sync data, rebuild, and stage changes:

```bash
deploy-and-push.bat
```

This script:
- Syncs data files from `heritage-app` to `heritage-app-site/data/`
- Rebuilds the Hugo site
- Rebuilds `index.json` (if you added new buildings)
- Rebuilds the Hugo site again (to pick up index changes)
- Stages all changes with `git add -A`
- Shows you what will be committed
- Prints the commit/push commands for you to run manually

## Project Structure

- `data/` - Synced data files (index.json, seed/*.md) - auto-synced by deploy script
- `content/` - Markdown content files
- `layouts/` - Hugo templates
- `static/` - Static assets (CSS, images)
- `public/` - Generated site output (not committed)
- `.github/workflows/deploy.yml` - GitHub Actions deployment workflow
